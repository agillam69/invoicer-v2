## Items explicitly excluded

- **MYOB / Xero accounting CSV export** — removed from scope. v1 `accounting_export.py` is not required for v2.

## Logging / note requirement for destructive actions

Every destructive or status-changing action must:

1. Prompt the user for an **optional note/reason** (where one is not already collected, e.g. Cancel/Void already collect a reason).
2. Write an entry to the **audit log** with:
   - `action` (e.g. `client_deleted`, `service_deleted`, `ledger_deleted`, `payment_reversed`)
   - `table_name` and `record_id`
   - `detail` containing the optional note/reason if provided.

Actions already covered by this requirement:

- Invoice **Cancel** / **Void** / **Manual record** (already logs).
- Payment **Reverse** (already logs).
- Client **Delete** and Service item **Delete** — log is not yet written; should be added when the note is captured.
- Future **Ledger delete** and **Backup restore** should also capture a note and log.

## Recommended order of work

1. **Payments → ledger mirroring** — small, high value, unblocks accurate P&L reporting.
2. **Client statement PDF** — high business value, self-contained.
3. **Data directory / OneDrive chooser** — small UX win.
4. **Settings fields** (PDF mode, report colours, backup config) — improves polish.
5. **Ledger edit/delete + categories + CSV** — larger but important for bookkeeping.
6. **Bank statement import** — large, but a major time-saver.
7. **Auto/scheduled backups** — depends on settings work.
8. **Reporting depth** — can be built incrementally as separate report tabs.
