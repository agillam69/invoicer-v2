## 1. Outstanding work (priority order)

### 1.1 Wire the single-instance Windows lock

**Why first:** it is small, low-risk, and should be in place before wider user testing of the packaged executable.

- Confirm `infrastructure/instance_lock.py` API.
- Call it from `app.py` / `__main__.py` before `QApplication` initialisation.
- Show a non-blocking message and exit if another instance is running.
- Add a unit/integration test for the lock helper.
- **Validation:** the test passes; running a second `InvoiceReceiptManager.exe` while one is open exits immediately.

### 1.2 Full data export to zip

**Why next:** it gives the user a safe, portable backup/transport bundle and supports the accountant hand-off use case.

- Add `application/export_service.py` (or extend existing) method `export_all_to_zip(path)`.
- Bundle:
  - business settings JSON,
  - clients, services, invoices, payments, ledger, audit CSVs,
  - generated documents (invoices, receipts, statements),
  - application logs.
- Add **Tools > Export all data to zip** menu item in `ui/main_window.py`.
- Add an integration test that exports and then verifies the archive contents.
- **Validation:** exported zip extracts and contains expected files; `pytest` passes.

### 1.3 Edit issued invoices

**Why after export/lock:** this is the most complex feature. Having a full export path makes it safe to test mutating issued data.

- Add a `reopen_for_edit(invoice, reason)` method to `application/invoice_service.py` that:
  - creates an audit entry,
  - removes existing PDF path references,
  - flips the invoice back to a special editable state (not a draft with a real number) or uses a new `editing` number prefix.
- Alternatively, implement an in-place `update_issued_invoice` that preserves payments by recomputing only line-item totals and creating an audit record.
- UI: add an **Edit** action on the `ui/invoice_list.py` context menu (only when the invoice has no payments/credits, or with a warning that totals will change).
- Rebuild the PDF and update `pdf_path` on save.
- Add integration tests for the workflow and audit log verification.
- **Validation:** an issued invoice can be edited, re-saved, re-PDFed, and the audit log records the reason; payments and balances remain correct.

### 1.4 Credit note UI

**Why after edit:** credit notes are logically related to post-issue invoice changes.

- Expose the existing `CreditNote` model in the UI.
- Add a **Credit note** action on `ui/invoice_list.py` and a `CreditNoteDialog`.
- Call `invoice_service.add_credit_note(...)` or create a new `application/credit_note_service.py`.
- Update invoice balance and status derivation, and ledger entries.
- Generate a credit-note PDF (optional but aligned with v1).
- Add integration tests for credit creation, ledger post, and balance update.
- **Validation:** a credit note reduces the invoice balance; ledger and reports reflect it correctly.

### 1.5 Accountant pack / year-end PDF

**Why later:** this is a reporting/printing deliverable and can be built once the invoice/ledger data flows are stable.

- Create `documents/accountant_pack_pdf.py` (already exists; verify and extend).
- Bundle into one PDF:
  - P&L summary for a selectable financial year,
  - GST collected/estimated credits,
  - Invoice register (issued, paid, overdue, cancelled),
  - Ledger register,
  - Client statement summary,
  - ATO/BAS summary page.
- Add a **Reports > Accountant Pack** button in `ui/reports_page.py`.
- Add a PDF test verifying each section is present.
- **Validation:** the generated PDF contains expected sections; `pytest` passes.

### 1.6 Build the Inno Setup installer

**Why last:** the executable must be finalised and smoke-tested before installer creation.

- Verify `installer/InvoiceReceiptManager.iss` matches the latest metadata.
- Install or locate `ISCC.exe`.
- Compile the `.iss` with the `dist\2.0.x\InvoiceReceiptManager.exe` from the latest build.
- Verify the installer runs, installs to `Program Files (x86)` or user-chosen location, and creates shortcuts.
- Update `docs/INSTALL.md` (or create) with install/run instructions.
- **Validation:** a clean Windows VM or account installs and launches the app.

## 2. Actual release cadence

When the plan was executed, the features listed above were already implemented from earlier work. They were therefore bundled into a single release rather than spread across multiple version bumps.

1. **2.0.6** — single-instance lock, full data export to zip, edit issued invoices, credit note UI, accountant pack PDF, and Inno Setup installer. This was the release that closed all remaining v1 parity and packaging gaps.
2. **2.0.7 onwards** — reserved for genuinely new work not already in the codebase.

For every future release:
- Update `pyproject.toml`, `src/invoice_manager/app.py`, and `installer/InvoiceReceiptManager.iss`.
- Run `ruff check src tests`.
- Run `mypy -p invoice_manager`.
- Run `pytest`.
- Rebuild `InvoiceReceiptManager.exe` to a versioned `dist\x.y.z` directory using a fresh `build-x.y.z` workpath.
- Rebuild `InvoiceReceiptManager_Setup.exe`.
- Record the executable and installer paths, sizes, and SHA-256s.
- Commit and push.
